# Real Life Notes — 需求分析文档

> 本文档是**后续迭代需求的唯一来源**。所有待规划、待实现的功能都从这里出发；`docs/requirements.md` 只记录**已被采纳并进入执行**的具体需求与决策。新增需求时：先在本文件补齐条目（含优先级与可行性）→ 采纳后写入 `requirements.md` 再动手。
>
> 硬约束：**纯静态、零后端、GitHub 仓库即数据库**。每条需求必须标注在此约束下的可行性，避免规划无法落地的功能。

---

## 1. 项目定位与核心约束

- **形态**：公共站点（`index.html` / `post.html?p=`）+ 管理后台（`admin/`），纯原生 JS，无构建步骤。
- **数据层**：`config.json` + `content/index.json` + `content/<分类>/<slug>.md` + `assets/images/`，一次发布 = 一个 commit 原子更新。
- **可用外部能力**：GitHub REST API（公开读 + PAT 私有写，无 CORS 限制）；GitHub Issues（天然评论系统）；浏览器 localStorage/IndexedDB/Web Crypto（本地数据）；GitHub Pages 构建（推送即发布）。
- **不可用能力**：任何服务端逻辑、Cron 定时任务、无授权第三方服务、需 OAuth 的秘密流程（已调研否决，见 `system-design.md`）。
- **部署形态**：GitHub Pages 多仓库/子路径（相对路径部署已支持），亦可部署到任意静态托管；实际经 Cloudflare 代理访问（有静态资源缓存，资源更新需递增 `?v=` 版本号）。

## 4. 详细需求（P0 优先）

### 4.1 R01 — 独立全文搜索索引 + 搜索建议

- **现状**：搜索在运行时用 `index.json` 内嵌 `content` 内存过滤；正文未内嵌的文章搜不到正文；无即时建议；大索引时首屏渲染负担大。
- **目标**：
  1. 管理后台发布时生成 `search-index.json`（词条 + 位置，或分片标题/摘要/正文/标签），公开站点直接 fetch 检索，检索与渲染解耦。
  2. 搜索框输入即时**联想/建议**（标题、标签前缀补全），可点击直达。
  3. 命中高亮（已有）、搜索词保留在分页链接（已有）、支持 `site:`/`tag:` 之类的简单检索语法（P1）。
- **可行性**：`search-index.json` 是纯静态文件，随内容 commit 生成（与 RSS 同链路）；前端 `Array.filter`/简单倒排即可，无需第三方。
- **影响面**：`admin.js`（生成）、`site.js`（读取+检索 UI）、`index.html`/`post.html`。

### 4.2 R02 — 评论能力增强（结合 R21 @提及）

- **现状**：GitHub Issues 评论只做简单正文展示，未渲染 Markdown；无排序切换、无分页加载；无法在评论里 @某人 并跳转。
- **目标**：
  1. 评论正文经 `md.render` 渲染（复用消毒管线）。
  2. 解析 `@用户名` → 链接到 `https://github.com/<用户>`（GitHub 侧本就会触发通知，前台仅做展示增强）。
  3. 排序切换（时间正序/倒序）、旧评论"加载更多"（分页拉 Issues API）。
  4. 展示作者头像（GitHub API `avatar_url`，需配置仓库可见性）。
  5. （P1）评论者若为仓库协作者/管理员，显示标识。
- **可行性**：全部基于 Issues API 已有数据，纯前端增强。

### 4.3 R03 — 文章封面/头图 + 图片懒加载与压缩

- **现状**：og:image 自动取正文首图，但文章无"封面"概念；列表卡片无图；上传图片不压缩。
- **目标**：
  1. frontmatter/index 新增可选 `cover` 字段；列表卡片可选展示封面；详情页顶部大图。
  2. 上传图片用 `canvas` 前端压缩（质量/尺寸上限，产出 WebP/JPEG），降低仓库体积与加载耗时。
  3. 正文图片默认 `loading="lazy"` + 宽高比占位（防布局抖动）。
- **可行性**：前端 canvas + FileReader 已可；`cover` 是索引字段增量，向后兼容。

### 4.4 R04 — 站内链接 / 双链笔记 + 反向链接

- **现状**：文章间只能手写相对 URL；无笔记关联关系。
- **目标**：
  1. 支持 `[[文章标题或 slug]]` 语法：渲染时按 `index.json` 解析为 `post.html?p=` 链接（不存在的目标显示为灰色占位）。
  2. 详情页"反向链接"区：列出所有引用本文的文章（索引内 O(n) 扫描，规模小可接受）。
  3. （P2）以反链数据绘制简单关系图。
- **可行性**：渲染阶段解析 + 索引扫描，纯前端；符合"笔记类"核心诉求。

### 4.5 R05 — 系列文章（series）

- **现状**：只能靠标签/相关文章串联，无法表达"本系列第 3/5 篇"。
- **目标**：
  1. frontmatter/index 新增可选 `series`（系列 id）与 `seriesOrder`（序号）。
  2. 详情页系列导航条：上一章/下一章 + 系列目录（按 `seriesOrder`）。
  3. 列表/归档可点击系列名查看全系列。
- **可行性**：索引字段增量，前后端少量改动。

### 4.6 R06 — 标签管理

- **现状**：标签只随单篇维护，无法合并/重命名/查重/看全部标签与计数；无标签专用后台页。
- **目标**：后台新增标签管理页：全部标签+计数、合并 A→B、重命名、删除空标签（批量重写 frontmatter + 索引，一次 commit）。
- **可行性**：与批量操作同思路（遍历改写），复用现有提交流程。

### 4.7 R07 — 定时发布（假定时）

- **现状**：只能立即发布或存草稿，无"计划发布"。
- **目标**：后台可选"计划发布时间"；索引写入 `scheduled` + `publishAt`；公开站点渲染时**未到时间视为草稿隐藏**（时间到了自然可见，无需定时器）。首页/RSS 同理过滤。
- **可行性**：纯静态可行（依赖访问时判断，无 server push）。注明局限：不会"准点出现"到访客刷新前。

### 4.8 R08 — 私密/密码文章

- **目标**：frontmatter 可选 `password`（存哈希，PBKDF2 经 Web Crypto）；详情页先显示密码框，校验后渲染；索引标记 `private: true`（列表显示锁图标、不输出到 RSS/sitemap）。
- **局限**：纯前端加密仅"防君子"（页面源码含算法），不用于强保密内容；作为"分享给特定人"场景足够。
- **可行性**：Web Crypto 原生支持；需注意 CSP 与浏览器兼容。

### 4.9 R09 — 关于页 / 作者页 / 友链页

- **目标**：后台可维护几个"静态页"（`about.md`、`friends.md` 等），站点导航出现对应入口；内容就是普通 Markdown 文章但走独立路由。
- **实现建议**：复用现有文章管线，给 `index.json` 条目加 `kind: "page"` 或在 `content/` 下建 `pages/` 目录，列表默认过滤、详情正常渲染。
- **可行性**：数据模型小扩展。

### 4.10 R10 — 面包屑导航

- **现状**：详情页有返回列表，但无"首页 / 分类 / 文章"层级路径。
- **目标**：详情页顶部面包屑（首页 → 分类名 → 当前标题），配 JSON-LD `BreadcrumbList`（增强 SEO）。
- **可行性**：纯前端。

### 4.11 R11 — 阅读量 / 热度统计

- **现状**：统计块只有"文章/分类/标签/字数"，无阅读量。
- **可选方案（按投入递增）**：
  1. **本地估算**（最省）：每次访问 localStorage 记最近 N 分钟去重，展示"本站热度"（量级指标，不精确）。
  2. **GitHub 聚合**：文章页面每次加载用 `GET /repos/.../commits?path=<文章>` 拉取该文件历史条数近似"被关注度"（无 token 限流需注意）。
  3. **仓库存储**（重）：每次浏览写一条 `data/views/<path>.json` 增量 commit —— **不建议**（会把仓库写爆）。
- **结论**：推荐方案 1 + 2 组合，标注"近似统计"，避免误导。热门文章榜单由此派生。

### 4.12 R12 — 媒体库管理

- **现状**：图片上传即走，无法复用/整理/删除旧图。
- **目标**：后台"图片库"：列出 `assets/images/` 全部图片（缩略图网格）、按文件名/日期筛选、复制 URL 插入正文、批量删除（一次 commit）。上传时支持选择已有图片复用。
- **可行性**：目录树 API + 索引本地列表。

### 4.13 R13 — 数据备份 / 导出

- **目标**：后台一键导出：拉取全部文章 md + 图片 + 索引，打包为 `.zip`（JSZip 本地托管）下载；或生成一份"迁移包"（README 说明目录结构，可导入其他静态博客）。
- **可行性**：纯前端 + 仓库只读 API；zip 用 vendored JSZip（CSP 内联允许）。

### 4.14 R14 — PWA

- **目标**：`manifest.webmanifest`（名称/图标/主题色）+ service worker（App Shell 缓存：HTML/CSS/JS/vendor；运行时缓存 `index.json`；离线可读已缓存文章）+ 可安装提示。
- **注意事项**：CSP 需允许 SW 作用域；本地与 Pages 子路径作用域处理；`index.json` 更新后缓存失效策略。
- **可行性**：纯静态天然支持；但需权衡缓存失效复杂度（与现有 `?v=` 版本号配合）。

### 4.15 R15 — 编辑器增强

- **目标**：工具栏（加粗/斜体/链接/代码/标题/列表/公式/表格/图片）、常用快捷键、正文插入图片与封面、侧边"写作信息"（字数/预估时长/标签）、全屏专注模式、（P2）字数进度条。
- **可行性**：前端编辑器增强，不涉及后端。

### 4.16 R16 — 分享扩展

- **目标**：在现有"复制链接"基础上，加一键分享到微博 / QQ / Telegram / X / 邮箱（`https://…/share?url=…` URL 拼接，新窗口打开）；微信无法直接分享 URL（只复制文案）。
- **可行性**：纯 URL 拼接，无 API 依赖。

### 4.17 R17 — 收藏 / 点赞

- **目标**：文章页"收藏/点赞"按钮；个人收藏清单存 localStorage（可导出）；可选"点赞数同步"到仓库的一个 `data/counters.json`（**有频率限制：做防抖合并、非每击一 commit**，否则写爆仓库）。
- **结论**：收藏（localStorage）落地无风险；点赞同步仓库需谨慎限流，列为 P1 可选。

### 4.18 R18 — 二级分类

- **目标**：`config.categories[key].parent`；列表/归档支持父子展开；导航按层级展示。
- **可行性**：配置与索引字段增量；注意与现有分类过滤/归档的 URL 兼容。

### 4.19 R19 — 版本历史 / 回滚

- **目标**：后台文章详情页展示该文件 Git 历史（`commits?path=`），可查看任一版本 diff、一键回滚到历史版本（重写文件+索引，一次 commit）。
- **可行性**：GitHub commits/contents API 即可。

### 4.20 R20 — RSS 增强

- **目标**：输出 Atom / JSON Feed 格式（可选）；RSS 全文/摘要切换（站点设置）；item 增加 `<updated>`、`<content:encoded>` 语言标记、（P2）per-category feed。
- **可行性**：`buildRss` 扩展，纯生成逻辑。

## 5. 不可行 / 需外部依赖（记录原因，避免反复评估）

| 需求 | 原因 |
| --- | --- |
| OAuth 登录（GitHub 账号体系） | `github.com/login/*` 无 CORS、需 client_secret，纯浏览器无法完成（已调研，见 `system-design.md`） |
| 真实 UV/PV/IP/地域统计 | 需服务端埋点或第三方脚本；纯前端只能近似 |
| 准点定时发布/服务器推 | 无 cron；仅能"到点后首次访问可见" |
| 邮件/微信推送通知 | 需第三方 API 与密钥 |
| 每阅读一次写仓库计数 | 会把 Git 仓库写爆，禁用 |
| 多作者登录与权限 | 需服务端集中密钥；备选 Workers 形态（`system-design.md` 形态 B） |
| 站内即时聊天 | 无 WebSocket/后端 |
| AI 问答 | 需外部 LLM 接口（Cloudflare Workers 可行，见 P2） |
